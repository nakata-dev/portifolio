🧩 Estilos Inline

Entenda o style="", quando evitar e como migrar para classes no CSS.

Voltar para HTML Contato

📌 O que é estilo inline?

  • Inline é CSS direto na tag: <h2 style="color: blue">
  • Vantagem: rápido para testar.
  • Desvantagem: repete muito, dificulta manutenção e padronização.
Regra prática: se você repetiu o mesmo style="" mais de 2 vezes, já merece virar classe.

🟢 Básico entender e reconhecer

Exemplo simples (inline). Funciona, mas fica difícil manter quando o site cresce. 

<h2 style="color: blue;">Título azul</h2>
<p style="font-size: 18px;">Texto maior</p>
Problema: você muda a cor em um lugar… e esquece dos outros 7.

⚖️ Comparação: “ruim” vs “bom”

🧱 Do jeito “ruim” (repetição)

Você começa assim, e quando vê… tem 40 inline espalhados. 

<h3 style="color: #0b66ff; margin-bottom:10px;">Capítulo 1</h3>
<p style="font-size:18px; line-height:1.8;">...</p>

<h3 style="color: #0b66ff; margin-bottom:10px;">Capítulo 2</h3>
<p style="font-size:18px; line-height:1.8;">...</p>

✅ Do jeito “bom” (classe)

Você centraliza a mudança no CSS, reaproveita e mantém o HTML limpo. 

<h3 class="title-blue">Capítulo 1</h3>
<p class="text-reading">...</p>

<h3 class="title-blue">Capítulo 2</h3>
<p class="text-reading">...</p>

/* CSS */
.title-blue{ color:#0b66ff; margin-bottom:10px; }
.text-reading{ font-size:18px; line-height:1.8; }

🟡 Intermediário migrar na prática

✅ Migração passo a passo (sem trauma)

  1. Identifique repetição: mesma cor, mesma fonte, mesmo espaçamento.
  2. Crie uma classe com nome claro: .title-blue, .text-reading.
  3. Substitua o inline por class="...".
  4. Teste em mobile e desktop.
Nome de classe bom é tipo etiqueta de gaveta: você encontra depois sem abrir tudo.

🔴 Avançado quando inline faz sentido + especificidade

Quando inline é aceitável (casos reais)

  • E-mails HTML: muitos clientes exigem inline para renderizar bem.
  • Prototipagem rápida: testar visual antes de “formalizar” em classes.
  • Variáveis dinâmicas (quando vem do JS): ex.: style="--progress: 70%".
Mas… em site/landing page normal, inline vira dívida técnica com juros altos.

Especificidade: por que inline “ganha”?

Inline geralmente tem prioridade maior que regras comuns do CSS. Por isso ele “briga” com seu site.css e dificulta ajustes.

Dica final: quando você precisar trocar uma cor, faça isso em 1 lugar (CSS), não em várias tags 😄

Resumo final

  • Inline é rápido, mas escala mal.
  • Classes deixam o HTML limpo e o CSS reutilizável.
  • Se repetiu, vira classe.
  • Inline pode “ganhar” na prioridade e bagunçar manutenção.

Mini-checklist

  • Removi inline repetido e criei classes.
  • Dei nomes claros às classes.
  • Testei no mobile (sem estourar layout).
  • O código ficou fácil de manter.
