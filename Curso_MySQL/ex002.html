Operações e melhorias no MySQL

Nesta aula você vai aprender a apagar e criar um banco, entender constraints e usar chave primária para impedir registros repetidos.

Apagando banco de dados

Use com cuidado. Esse comando apaga o banco inteiro com tudo dentro. 

drop database cadastro;

Criando banco de dados

O comando abaixo cria um banco simples com o nome cadastro. 

create database cadastro;
Voltar

Constraint (restrições)

No contexto de banco de dados, uma constraint é uma regra de integridade que o próprio banco impõe aos dados de uma tabela para garantir que as informações sejam corretas e consistentes.

Exemplos: not null, default, enum, primary key ✅

Criando banco com UTF-8 + tabela com constraints

Aqui você cria o banco com charset e collate corretos, usa o banco e cria a tabela pessoas. 

create database cadastro
default character set utf8
default collate utf8_general_ci;

use cadastro;

create table pessoas(
nome varchar(30) not null,
nascimento date,
sexo enum ('M','F'),
peso decimal(5,2),
altura decimal(3,2),
nacionalidade varchar(20) default 'Brasil'
) default charset = utf8;
Voltar
O que foi usado:
not null (não pode ser nulo) · date (data) · enum('M','F') (escolher entre opções) · decimal(5,2) (5 casas no total, 2 após a vírgula) · default 'Brasil' (valor padrão)

Para evitar repetição de cadastro

A solução profissional é criar um campo id com auto incremento e definir como chave primária. 

create database cadastro
default character set utf8
default collate utf8_general_ci;

use cadastro;

create table pessoas(
id int not null auto_increment,
nome varchar(30) not null,
nascimento date,
sexo enum ('M','F'),
peso decimal(5,2),
altura decimal(3,2),
nacionalidade varchar(20) default 'Brasil',
primary key(id)
) default charset = utf8;
Voltar
Resumo rápido:
auto_increment cria um ID único automaticamente ✅
primary key impede duplicidade e vira o identificador oficial da tabela.
