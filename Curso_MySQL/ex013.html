🧠 INNER JOIN

por: Ailton A. Nakata

🧠 Criando tabela extra:

    
use cadastro;

create table gafanhoto_assite_curso(
id int not null auto_increment,
data date,
idgafanhoto int,
idcurso int,
primary key(id),

foreign key(idgafanhoto) references gafanhotos(id),
foreign key(idcurso) references cusos(idcurso)

) default charset = utf8;

🧠 O que significa “foreign key”?

    
Foreign Key (chave estrangeira) é um tipo especial de coluna que liga uma tabela a outra.

Ela serve para garantir integridade entre os dados — ou seja, evita que existam registros “sem conexão” entre as tabelas

📘 Tradução em português simples:

    
“A coluna idgafanhoto desta tabela está ligada à coluna id da tabela gafanhotos.”

“A coluna idcurso desta tabela está ligada à coluna idcurso da tabela cursos.”

Inserindo valores na tabela:

    
insert into gafanhoto_assite_curso values
(default, '2024-03-01', '1','2');

Junções:

Como fica na prática?

    
SELECT g.nome, c.nome
FROM gafanhotos g
JOIN gafanhoto_assiste_curso a
ON g.id = a.idgafanhoto
JOIN cursos c
ON c.idcurso = a.idcurso
ORDER BY g.nome;

Explicação final

🧩 Temos 3 tabelas:

    
gafanhotos → onde estão os alunos
    👉 contém id e nome

cursos → onde estão os cursos
    👉 contém idcurso e nome

gafanhoto_assiste_curso → faz a ponte entre os dois
    👉 contém idgafanhoto e idcurso

💬 Pensando em linguagem humana:

    
“Quero ver o nome de cada gafanhoto junto com o nome do curso que ele assiste.”

Mas como cada aluno pode estar em vários cursos, e cada curso pode ter vários alunos, precisamos ligar as tabelas de forma organizada.
