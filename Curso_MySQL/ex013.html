INNER JOIN

Aqui você vai entender como funciona o relacionamento muitos para muitos, criando uma tabela associativa e conectando tudo com JOIN.

Relação muitos-para-muitos na prática

Um aluno pode fazer vários cursos. E um curso pode ter vários alunos. Resultado: precisamos de uma tabela ponte 🧩

Criando tabela extra (tabela associativa)

Essa tabela guarda quem assistiu qual curso e em qual data. 

use cadastro;

create table gafanhoto_assiste_curso(
  id int not null auto_increment,
  data date,
  idgafanhoto int,
  idcurso int,
  primary key(id),
  foreign key (idgafanhoto) references gafanhotos(id),
  foreign key (idcurso) references cursos(idcurso)
) default charset = utf8;
Voltar
Dica: essa tabela é conhecida como tabela associativa ✅

O que significa “FOREIGN KEY”?

Foreign Key (chave estrangeira) é um tipo especial de coluna que liga uma tabela a outra.

Ela serve para garantir integridade entre os dados,
evitando registros “sem conexão” entre as tabelas.
Voltar

Tradução em português simples

“A coluna idgafanhoto desta tabela está ligada à coluna id da tabela gafanhotos.”

“A coluna idcurso desta tabela está ligada à coluna idcurso da tabela cursos.”

Junções (muitos para muitos)

Como fica na prática?

Agora juntamos as 3 tabelas com um JOIN triplo. 

select g.nome, c.curso
from gafanhotos g
join gafanhoto_assiste_curso a
  on g.id = a.idgafanhoto
join cursos c
  on c.idcurso = a.idcurso
order by g.nome;
Voltar
Objetivo: “Quero ver o nome de cada gafanhoto junto com o curso que ele assiste.” ✅

Explicação final

🧩 Temos 3 tabelas:

gafanhotos → onde estão os alunos
  👉 contém id e nome

cursos → onde estão os cursos
  👉 contém idcurso e curso

gafanhoto_assiste_curso → faz a ponte entre os dois
  👉 contém idgafanhoto e idcurso
Voltar

Como cada aluno pode estar em vários cursos e cada curso pode ter vários alunos, usamos a tabela associativa para organizar isso certinho ✅
