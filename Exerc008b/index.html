Código fonte: <code> e <pre>

Básico (o que você precisa hoje)

Use <code> para marcar trechos de código dentro do texto. Quando o código tem várias linhas (ou precisa manter espaços e indentação), use <pre><code>...</code></pre>.

Intermediário (pra ficar “profissional”)

  • Inline (1 linha): <code> dentro do parágrafo.
  • Bloco (várias linhas): <pre><code> para preservar quebras/identação.
  • Legibilidade: prefira exemplos curtos e bem indentados.
🧠 Por que isso importa? Marcar código corretamente melhora leitura, acessibilidade e permite que ferramentas (incluindo buscadores) entendam que aquilo é “código”, não texto comum.

Avançado (boas práticas + pegadinhas)

  • Pegadinha clássica: se você escrever <div> dentro de um <code>, o navegador pode interpretar como HTML. Para exibir “as tags”, escape: &lt;div&gt;.
  • Não use <pre> para “organizar layout” (isso é trabalho do CSS).
  • Para ensinar “entrada/saída” em exemplos, existe uma trinca útil: <kbd> (teclas/entrada), <samp> (saída) e <code> (código).

🔎 Exemplo (bloco de código)

num = int(input("Digite um número"))
if num % 2 == 0:
    print(f"O número {num} é PAR")
else:
    print(f"O número {num} é ÍMPAR")

print("Fim do programa")
✅ Dica: se o exemplo for HTML, lembre de escapar as tags dentro do <code>: escreva &lt;h1&gt; em vez de <h1>.

🔎 Exemplo (entrada/saída com <kbd> e <samp>)

Quando você quer explicar “o que eu digito” vs “o que aparece”, fica bem claro assim: 

<p>Digite: <kbd>npm run dev</kbd></p>
<p>Resultado: <samp>Servidor iniciado em http://localhost:5173</samp></p>

Visual: Digite npm run dev • Resultado: Servidor iniciado em http://localhost:5173

Resumo (bullet points)

  • <code> = trecho de código (inline).
  • <pre><code> = bloco com indentação preservada.
  • Escape HTML dentro do código: &lt; &gt; &amp;.

Mini-checklist

  • Usei <code> para trechos curtos.
  • Usei <pre><code> para blocos.
  • Escapei tags HTML dentro do código.

Perguntas rápidas (fixação)

  1. Quando você usa <pre> junto do <code>?
  2. Por que <pre> não é uma boa ideia para “fazer layout”?
  3. Como você exibe <h1> dentro de um bloco de código sem virar HTML?

Citações curtas: <q>

Básico

Use <q> para uma citação curta dentro da frase. O navegador geralmente coloca aspas automaticamente.

🔎 Exemplo

Um lembrete que salva tempo: se algo pode dar errado, teste primeiro no menor exemplo possível.

Código do exemplo:

<p>Um lembrete que salva tempo: <q>se algo pode dar errado, teste primeiro no menor exemplo possível.</q></p>
⚠️ Atenção: <q> é para citação curta. Se a citação vira um “parágrafo inteiro”, use <blockquote>.

Intermediário

  • Você pode usar o atributo cite para apontar a fonte (URL).
  • Mesmo com cite, normalmente é melhor mostrar a fonte como link para o leitor.

Avançado

  • As aspas podem variar conforme idioma/navegador. Se você precisa de aspas “exatas”, estilize via CSS (sem brigar com a semântica).
  • Evite usar <q> só para “colocar aspas”. Use quando for de fato uma citação.

Resumo

  • <q> = citação curta na mesma linha.
  • Para trechos longos: <blockquote>.

Mini-checklist

  • Usei <q> apenas para citações curtas.
  • Não transformei parágrafos inteiros em <q>.

Perguntas rápidas

  1. Quando <q> vira uma má escolha?
  2. O que você usa no lugar para uma citação longa?

Citações longas: <blockquote> e fonte

Básico

Use <blockquote> quando a citação é grande e faz sentido visualmente como bloco. Você pode indicar a fonte com o atributo cite (URL).

🔎 Exemplo (citação em bloco)

Em HTML, uma boa prática é escolher o elemento certo para o “tipo de informação” que você está marcando. Citações longas pedem blockquote; citações curtas na frase pedem q.

Fonte (visível para o leitor): MDN: blockquote

Código do exemplo:

<blockquote class="quote" cite="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/blockquote">
  Em HTML, uma boa prática é escolher o elemento certo...
</blockquote>

<p>Fonte: <a href="https://developer.mozilla.org/en-US/docs/Web/HTML/Element/blockquote">MDN: blockquote</a></p>
✅ Dica: o atributo cite é ótimo para “metadado”, mas o leitor agradece quando você mostra a fonte como um link claro.

Intermediário (entendendo <cite>)

A tag <cite> marca o título de uma obra (livro, artigo, filme, música). Ela não serve para “colocar URL” e não é a mesma coisa que o atributo cite.

🔎 Exemplo (com <cite> do jeito certo)

Eu aprendi isso lendo HTML: HyperText Markup Language na MDN.

Código do exemplo:

<p>Eu aprendi isso lendo <cite>HTML: HyperText Markup Language</cite> na MDN.</p>
⚠️ Pegadinha comum: muita gente usa <cite> como “fonte/autor/URL”. Na prática, <cite> é o título da obra. Para URL, use link (<a>).

Resumo

  • <blockquote> = citação longa em bloco.
  • cite="URL" = URL da fonte (metadado).
  • <cite> = título de obra (texto).

Mini-checklist

  • Usei <blockquote> só quando era citação longa.
  • Deixei a fonte visível com um link.
  • Usei <cite> apenas como título de obra.

Perguntas rápidas

  1. Qual a diferença entre cite atributo e <cite> tag?
  2. Quando você troca <q> por <blockquote>?

Abreviações: <abbr>

Básico

Use <abbr> para marcar siglas/abreviações. No title, você coloca o significado completo. Em muitos navegadores, isso vira um “tooltip”.

🔎 Exemplo

Estou estudando HTML e CSS. Próximo passo: JS.

Código do exemplo:

<p>
  Estou estudando <abbr title="HyperText Markup Language">HTML</abbr> e
  <abbr title="Cascading Style Sheets">CSS</abbr>.
  Próximo passo: <abbr title="JavaScript">JS</abbr>.
</p>
✅ Dica: no primeiro uso, você pode escrever o termo completo no texto e a sigla depois: “HyperText Markup Language (HTML)”. Isso ajuda todo mundo, mesmo sem tooltip.

Intermediário

  • Use title com a expansão humana (nada de “texto genérico”).
  • Se a sigla for muito importante no contexto, explique no conteúdo também (tooltip não é garantido para todos).

Avançado (boas práticas + pegadinhas)

  • Pegadinha: depender só do tooltip pode falhar em touch (celular) e alguns leitores de tela.
  • Evite siglas “misteriosas” em textos de onboarding. Expanda pelo menos uma vez.

Resumo

  • <abbr title="...">SIGLA</abbr> = sigla com explicação.
  • Explique no texto no primeiro uso quando for importante.

Mini-checklist

  • Adicionei title com o significado completo.
  • Não deixei siglas importantes sem explicação.

Perguntas rápidas

  1. O que você coloca dentro do title no <abbr>?
  2. Por que é ruim depender só do tooltip no celular?

Texto invertido: <bdo>

Básico

O <bdo> força a direção do texto com o atributo dir: rtl (direita → esquerda) ou ltr (esquerda → direita).

🔎 Exemplo

Texto invertido / Texto normal.

Código do exemplo:

<p><bdo dir="rtl">Texto invertido</bdo> / Texto normal.</p>
⚠️ Atenção: <bdo> é uma “ferramenta forte”. Use quando você realmente precisa sobrescrever a direção do texto. Para textos com direção desconhecida (por exemplo, vindo de um banco de dados), muitas vezes <bdi> é mais seguro.

Intermediário

  • Use dir="rtl" ao exibir exemplos de idiomas RTL (árabe, hebraico) em um site LTR.
  • Use dir="ltr" quando o texto precisa ficar “normal” dentro de um contexto RTL.

Avançado (bônus útil: <bdi>)

<bdi> isola um trecho que pode ter direção diferente do resto. É perfeito para “usernames” e textos mistos, onde o algoritmo bidi pode confundir a ordem.

Exemplo: Usuário مستخدم123 comentou no post.

Código do exemplo:

<p>Exemplo: Usuário <bdi dir="auto">مستخدم123</bdi> comentou no post.</p>

Resumo

  • <bdo dir="rtl"> = força direção (override).
  • <bdi dir="auto"> = isola texto de direção incerta (mais seguro em dados dinâmicos).

Mini-checklist

  • Usei <bdo> só quando precisei sobrescrever direção.
  • Considerei <bdi> para textos dinâmicos.

Perguntas rápidas

  1. Qual atributo é obrigatório no <bdo>?
  2. Quando <bdi> é melhor do que <bdo>?

Resumo geral (em 30 segundos)

  • Código: <code> (curto) e <pre><code> (bloco).
  • Citações: <q> (curta) e <blockquote> (longa). <cite> = título da obra.
  • Siglas: <abbr title="...">.
  • Direção: <bdo> para override, <bdi> para isolar texto incerto.
