Imagens dinâmicas (responsivas)

Básico

Imagem responsiva é quando o navegador escolhe a melhor versão da imagem para cada tela. Isso evita “mandar um caminhão” (imagem gigante) para um celular que só precisa de uma versão menor.

🧠 Por que isso importa? Menos peso = carregamento mais rápido, menos consumo de dados e mais chance do usuário continuar na página.
  • Você controla a troca com <picture> + <source media="...">.
  • O <img> fica por último como fallback (se nada bater, ele entra).

Intermediário

Existem dois jeitos comuns de “responsivar” imagens:

  • Art direction (trocar a imagem mesmo): use <picture>. Ex.: no mobile, uma foto mais “quadrada” e no desktop, uma mais “paisagem”.
  • Mesma imagem, vários tamanhos: use srcset + sizes no <img>. Ex.: mesma foto, mas com 480/960/1440px para diferentes telas e densidades.

🔎 Exemplo (mesma imagem com srcset + sizes):

<img
  src="imagens/exemplo-700.jpg"
  srcset="
    imagens/exemplo-300.jpg 300w,
    imagens/exemplo-700.jpg 700w,
    imagens/exemplo-1000.jpg 1000w
  "
  sizes="(max-width: 700px) 300px, (max-width: 1000px) 700px, 1000px"
  alt="Foto responsiva com srcset e sizes"
  loading="lazy"
/>
✅ Dica: sizes é o “mapa” dizendo quanto espaço a imagem ocupa no layout. Sem ele, o navegador pode baixar uma versão maior do que precisa.

Avançado (boas práticas e pegadinhas)

  • Ordem importa: em <picture>, coloque primeiro o source mais específico (geralmente o menor breakpoint).
  • Use type: ajuda o navegador a decidir mais rápido (ex.: image/avif, image/webp, image/jpeg).
  • Nomeie versões com lógica: foto-300, foto-700, foto-1000. Sua futura versão agradece.
  • Alt não é enfeite: descreva a imagem com clareza (ou use alt="" se for decorativa).
  • Evite PNG “à toa”: para fotos, JPEG/WebP/AVIF geralmente pesam menos. PNG é ótimo para transparência e imagens “chapadas”.

Perguntas rápidas (fixação)

  1. Quando você usa <picture> (art direction) em vez de só srcset?
  2. Para que serve o sizes?
  3. Por que o <img> precisa existir dentro do <picture>?

  • Use <picture> quando quiser trocar a imagem conforme o breakpoint (art direction).
  • Use srcset + sizes quando for a mesma imagem em resoluções diferentes.
  • Alt descritivo e imagens otimizadas são metade da vitória.

Áudio em HTML5

Básico

Para colocar áudio na página, você usa <audio>. O essencial para o usuário é: controls (botões de play, pause, volume).

🧠 Por que isso importa? Áudio sem controle costuma irritar. Áudio com controle vira recurso: aula, podcast, trilha de demonstração, pronúncia, etc.

Intermediário

  • 1 arquivo no src: simples e rápido para começar.
  • Múltiplos <source>: mais compatível (o navegador escolhe o que suporta).
  • preload controla pré-carregamento: none, metadata (recomendado), ou auto (pode pesar).
⚠️ Atenção: autoplay com som quase sempre é bloqueado. O navegador geralmente exige uma ação do usuário (clique/toque) antes de tocar áudio.

Avançado (boas práticas e pegadinhas)

  • Compatibilidade: a combinação mais segura costuma ser MP3 + OGG. WAV é enorme e raramente necessário.
  • Performance: prefira preload="metadata" para não baixar o áudio inteiro sem necessidade.
  • Acessibilidade: se o áudio for conteúdo importante, ofereça um resumo ou transcrição na página.
  • Controle por clique: se você quiser “play” por botão customizado, faça isso após uma interação do usuário.

🔎 Exemplo (play só depois do clique):

<audio id="audio-aula" src="midias/happy-mistake.mp3" preload="metadata"></audio>
<button type="button" id="btn-play">Tocar áudio</button>

<script>
  const audio = document.getElementById('audio-aula');
  const btn = document.getElementById('btn-play');

  btn.addEventListener('click', async () => {
    try {
      await audio.play();
      btn.textContent = 'Tocando...';
    } catch (e) {
      alert('O navegador bloqueou a reprodução. Tente clicar novamente.');
    }
  });
</script>

Perguntas rápidas (fixação)

  1. Qual atributo mostra os botões do player?
  2. Por que o autoplay com som costuma falhar?
  3. Qual valor de preload é o mais equilibrado na maioria dos casos?

Existem duas formas comuns: apontar direto no src ou usar múltiplos <source> (mais compatível). Observação: autoplay costuma ser bloqueado pelos navegadores.

1) Audio com src

Básico

Esse é o jeito mais rápido: um arquivo MP3 direto no src + controls. 

<audio src="midias/happy-mistake.mp3" controls preload="metadata"></audio>
✅ Dica: preload="metadata" pega só informações (duração etc.) sem baixar tudo.

2) Audio com múltiplos formatos

⚠️ Atenção: wav costuma ser pesado. Prefira mp3 e ogg quando possível.

Intermediário

Com múltiplos <source>, você dá opções. O navegador escolhe o primeiro formato compatível e ignora o resto. 

<audio controls preload="metadata">
  <source src="midias/happy-mistake.mp3" type="audio/mpeg">
  <source src="midias/happy-mistake.ogg" type="audio/ogg">
  <p>Seu navegador não suporta áudio.</p>
</audio>
✅ Dica: se você quer cobertura boa, foque em MP3 + OGG. WAV só se houver motivo forte.

Resumo final (Áudio)

  • Use controls para não “sequestrar” a experiência do usuário.
  • Múltiplos <source> aumentam compatibilidade.
  • preload="metadata" costuma ser a escolha mais segura para performance.
  • Autoplay com som geralmente depende de clique do usuário.

Mini-checklist (Áudio)

  • O player tem controls?
  • Usei ao menos MP3 + OGG (se preciso)?
  • Evitei WAV a menos que fosse necessário?
  • Se eu quis autoplay, eu amarrei ao clique do usuário?
