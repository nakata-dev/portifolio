Tags Obsoletas

Como identificar recursos antigos (deprecated), evitar problemas de acessibilidade/compatibilidade e trocar por alternativas modernas (sem “gambiarra”).

Voltar para HTML Contato

Onde conferir a lista oficial

Você pode ver a lista completa de elementos e atributos obsoletos/deprecated na documentação oficial. Isso é o “mapa do tesouro” para não usar algo que ainda funciona hoje, mas vira dor de cabeça amanhã.

Básico (para iniciantes)

Quando uma tag/atributo é marcado como deprecated (ou obsoleto), a regra é simples: evite usar. Pode continuar “rodando” em alguns navegadores, mas você perde previsibilidade.

🧠 Por que isso importa? HTML é uma linguagem “de longo prazo”. Se você aprende o caminho moderno (semântico + CSS), seu código dura mais e dá menos manutenção.

Intermediário (onde olhar de verdade)

  • HTML Living Standard (WHATWG): seção “Obsolete features” (lista viva e atualizada).
  • MDN: páginas de cada tag avisam quando é deprecated e mostram alternativa.
  • W3C (HTML5/HTML 5.2): listas históricas úteis para entender “o que caiu em desuso”.

Links úteis (oficiais):

  • WHATWG: Obsolete features (Living Standard)
  • W3C (HTML5 - 2014): Obsolete features (referência histórica)

Avançado (pegadinhas de termos)

  • “Deprecated” normalmente significa: “não recomendo usar, pode sumir/variar, tem alternativa melhor”.
  • “Obsolete” aparece bastante em especificações e listas históricas. Em muitos lugares (como na própria MDN), essa distinção nem é tão útil no dia a dia: o que importa é evitar e substituir.

✅ Dica: achou uma tag “diferentona” em um tutorial antigo? Joga o nome no MDN antes de copiar. Isso evita pegar “HTML fóssil” por acidente.

Resumo final

  • Confira no WHATWG (lista viva)
  • Use MDN para ver avisos e alternativas
  • W3C ajuda como referência histórica

Mini-checklist

  • Eu verifiquei a tag no MDN/WHATWG?
  • Existe alternativa semântica + CSS?
  • Isso pode afetar acessibilidade (movimento, leitura, navegação)?

  1. Qual fonte você consulta para uma lista “viva” de recursos obsoletos?
  2. Por que um tutorial antigo pode ser perigoso de copiar?
Por que evitar? Tags/atributos obsoletos podem falhar em navegadores, atrapalhar leitores de tela e dificultar manutenção do site. Trocar por HTML semântico + CSS deixa tudo mais previsível.

🔎 “Top 3” de coisas antigas que ainda aparecem por aí

Aqui vão exemplos bem comuns em conteúdos antigos, com a alternativa moderna (e mais profissional).

1) <center> (centralizar conteúdo) 

<!-- Evite (deprecated) -->
<center>Texto centralizado</center>

<!-- Prefira (CSS) -->
<p style="text-align:center;">Texto centralizado</p>

2) <font> (cor/tamanho/fonte “na unha”) 

<!-- Evite (deprecated) -->
<font color="red" size="5">Promoção!</font>

<!-- Prefira (CSS) -->
<span style="color:#e11d48; font-size:1.25rem; font-weight:700;">Promoção!</span>

3) Atributos de “layout” no HTML (ex.: bgcolor, width, etc.) 

<!-- Evite: mistura conteúdo + estilo -->
<table bgcolor="#000" width="100%">...</table>

<!-- Prefira: estilo no CSS -->
<table class="tabela">...</table>
<style>
  .tabela{ width:100%; background:#000; }
</style>
✅ Dica: a regra de ouro é: HTML diz o que é (estrutura/semântica), e CSS diz como parece (estilo).

Exemplo: a tag <marquee>

Marquee serve para fazer este letreiro se movimentar na tela.

Apesar de funcionar em alguns navegadores, <marquee> é considerado um recurso obsoleto: é “apresentacional”, foge do controle moderno e pode prejudicar acessibilidade.

Básico

O <marquee> cria um texto rolando automaticamente. Parece divertido, mas é o tipo de coisa que você encontra em código antigo.

Intermediário

  • Problema 1: você tem pouco controle fino (velocidade, pausa, responsividade).
  • Problema 2: movimento automático pode incomodar usuários sensíveis a animações.
  • Problema 3: não é o “padrão da web moderna”. Hoje fazemos isso com CSS (ou JS, se necessário).

Avançado (pegadinha importante)

⚠️ Atenção: animações sem respeitar prefers-reduced-motion podem causar desconforto em algumas pessoas. Sempre que possível, ofereça versão sem movimento.

Resumo final

  • <marquee> é legado e não recomendado
  • Use CSS para controlar melhor e ficar consistente
  • Respeite prefers-reduced-motion

Mini-checklist

  • Tenho um motivo real para animar?
  • Consigo pausar/desativar o movimento?
  • Respeito prefers-reduced-motion?

Alternativa moderna (CSS)

Em vez de <marquee>, você pode animar com CSS. Abaixo vai um exemplo simples, com pausa no hover e respeito ao prefers-reduced-motion. 

<div class="ticker" aria-label="Letreiro animado">
  <div class="ticker-track">Letreiro animado com CSS (mais controlável e acessível).</div>
</div>

<style>
  .ticker{
    overflow:hidden;
    border:1px dashed rgba(0,0,0,.2);
    border-radius:12px;
    padding:12px;
    background:#fff;
  }
  .ticker-track{
    display:inline-block;
    white-space:nowrap;
    will-change: transform;
    animation: ticker 10s linear infinite;
  }
  .ticker:hover .ticker-track{
    animation-play-state: paused;
  }
  @keyframes ticker{
    from { transform: translateX(100%); }
    to   { transform: translateX(-100%); }
  }
  @media (prefers-reduced-motion: reduce){
    .ticker-track{ animation:none; }
  }
</style>
✅ Dica: o trecho prefers-reduced-motion respeita usuários que preferem menos animação. E o “pausar no hover” ajuda quem quer ler com calma.

Básico

Você cria uma “janela” (.ticker) e move o texto dentro dela (.ticker-track) com @keyframes.

Intermediário

  • Controle: velocidade (tempo), direção (keyframes) e pausa.
  • Responsivo: funciona melhor com layouts modernos.
  • Manutenção: sem depender de tags antigas.

Avançado (boas práticas)

  • Respeite preferências do usuário: prefers-reduced-motion é um cuidado real de acessibilidade.
  • Evite exagero: animação deve ter motivo. Se for só “enfeite”, considere não usar.
  • Performance: animar transform costuma ser mais suave do que mexer em propriedades de layout.

Resumo final

  • CSS substitui marquee com controle total
  • Inclua pausa e reduced-motion
  • Priorize leitura e acessibilidade

Mini-checklist

  • Tenho @media (prefers-reduced-motion: reduce)?
  • O usuário consegue ler (pausa/velocidade)?
  • A animação é necessária?
