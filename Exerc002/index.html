Quebra de linha (<br>)

Use <br> para quebrar linha dentro de um texto. Mais tarde, a gente substitui “espaçamento” por CSS (margin/padding), mas para começar é ótimo.

Básico

O <br> força uma nova linha no mesmo bloco de texto. Pense nele como “Enter” dentro de uma frase.

🧠 Por que isso importa? O <br> é para quebras que fazem parte do conteúdo (ex.: endereço, poesia, letras de música), e não para “empurrar” elementos na tela. :contentReference[oaicite:0]{index=0}

Intermediário

  • Use quando a quebra é semântica: endereço, versos, assinaturas.
  • Evite para espaçamento: não use vários <br> para “criar distância” entre blocos. :contentReference[oaicite:1]{index=1}
  • Para espaçamento profissional: use CSS com margin e padding em elementos como <p>, <section>, <div>.

Avançado (boas práticas e pegadinhas)

  • Pegadinha: muitos <br> viram “gambiarra visual” e quebram fácil no mobile.
  • Semântica: se você está separando parágrafos, use <p> e CSS, não <br>. :contentReference[oaicite:2]{index=2}
  • Legibilidade: quando o conteúdo cresce, espaçamento via CSS mantém tudo consistente.

✅ Dica: Regra de ouro: <br> quebra linha. CSS dá espaço.

🔎 Exemplo (quando faz sentido): endereço

<p>
Rua Exemplo, 123<br>
Centro<br>
São Paulo - SP
</p>

🔎 Exemplo (o que evitar): usar <br> como espaçador

<!-- Evite isso: espaçamento “na marra” -->
<h2>Título</h2>
<br><br><br>
<p>Texto...</p>

<!-- Prefira: CSS no elemento (margin/padding) -->

Resumo final

  • <br> quebra linha dentro do conteúdo
  • Não use <br> para criar “espaço” entre blocos :contentReference[oaicite:3]{index=3}
  • Espaçamento consistente = CSS (margin/padding)

Mini-checklist

  • Eu usei <br> só quando a quebra faz parte do conteúdo?
  • Se eu queria “espaço”, eu deixei isso para o CSS?

Perguntas rápidas

  1. Em que caso <br> é melhor do que criar um novo parágrafo?
  2. Por que usar vários <br> para espaçar é uma má ideia?

Linha Horizontal (<hr>)

A tag <hr> cria uma linha divisória. Mas ela não é só “decoração”: tecnicamente, ela indica uma quebra temática (mudança de assunto dentro de uma seção). :contentReference[oaicite:4]{index=4}

Básico

Use <hr> quando você quer separar partes do conteúdo com uma linha. Exemplo simples: “antes” e “depois”, “introdução” e “próximos passos”.

Intermediário

No HTML moderno, <hr> representa uma quebra temática entre elementos de nível de parágrafo. É como trocar de capítulo dentro do mesmo tópico. :contentReference[oaicite:5]{index=5}

🧠 Por que isso importa? Semântica ajuda na manutenção e na leitura. Se a linha marca uma “mudança de assunto” de verdade, <hr> é adequado. Se for só estética, CSS costuma ser melhor. :contentReference[oaicite:6]{index=6}

Avançado (boas práticas e pegadinhas)

  • Pegadinha: usar <hr> em todo lugar como “linha bonita”. Isso polui o HTML e perde o sentido. :contentReference[oaicite:7]{index=7}
  • Semântica: se a separação é de “assunto”, ótimo. Se é apenas “estilo”, prefira CSS.
  • Acessibilidade/estrutura: o navegador e ferramentas podem interpretar a quebra temática.

🔎 Exemplo (mudança de assunto):

<p>Agora você já sabe o básico do HTML.</p>
<hr>
<p>Próximo tema: como organizar títulos (h1, h2, h3).</p>

✅ Dica: quer uma linha “só visual” com mais controle?

<!-- Em vez de depender do padrão do <hr>, você pode estilizar com CSS -->
<hr class="meu-separador">

/* CSS (exemplo) */
.meu-separador { opacity: .25; }

Resumo final

  • <hr> marca uma quebra temática (mudança de assunto) :contentReference[oaicite:8]{index=8}
  • Se for só estética, CSS pode ser melhor
  • Use com intenção, não por hábito

Mini-checklist

  • Essa linha realmente separa assuntos diferentes?
  • Se for só visual, eu poderia resolver com CSS?

Perguntas rápidas

  1. O que significa “quebra temática” no contexto do <hr>?
  2. Quando CSS é melhor do que <hr>?

Símbolos especiais

® © ™ € £ ¥ ¢ Δ

Eles são úteis para páginas institucionais (copyright, marcas, moeda, etc).

Básico

Alguns símbolos não aparecem fácil no teclado (ou podem quebrar o HTML se digitados do jeito errado). Para isso existem as referências de caracteres (também chamadas “entities”). :contentReference[oaicite:9]{index=9}

⚠️ Atenção: Caracteres reservados do HTML precisam de “escape”. Exemplo clássico: < vira &lt; e & vira &amp;. :contentReference[oaicite:10]{index=10}

Intermediário

  • Você pode usar nome (ex.: &copy;) ou número (ex.: &#169;).
  • Também existe o formato hexadecimal: (ex.: &#x00A9;). :contentReference[oaicite:11]{index=11}
  • Numeric (decimal/hex) é ótimo quando você não lembra o nome da entidade.

🔎 Exemplo (3 jeitos de escrever €):

<p>Euro com nome: &euro;</p>
<p>Euro em decimal: &#8364;</p>
<p>Euro em hex: &#x20AC;</p>

Avançado (boas práticas e pegadinhas)

  • Consistência: escolha um padrão (nome OU numérico) e mantenha no projeto.
  • Legibilidade: nomes (&copy;) são mais fáceis de ler; numéricos são mais universais. :contentReference[oaicite:12]{index=12}
  • Pegadinha: esquecer o ; no fim (ex.: &copy) pode não funcionar em alguns casos.

✅ Dica: Se você não sabe o código de um símbolo, procure pelo “character reference” e copie a entidade certinha. :contentReference[oaicite:13]{index=13}

Resumo final

  • Entities são “atalhos” para representar caracteres no HTML :contentReference[oaicite:14]{index=14}
  • Existem nomes (&copy;) e números (&#169; / &#x00A9;)
  • Caractere reservado (<, &) precisa de escape

Mini-checklist

  • Eu usei ; no fim da entidade?
  • Eu escapei < e & quando necessário?

Perguntas rápidas

  1. Qual a diferença entre entidade por nome e por número?
  2. Por que < não deve ser digitado “cru” dentro de texto HTML?

Emojis no HTML

Você pode inserir emojis usando Unicode. O jeito mais simples é copiar e colar o emoji no HTML (já que sua página está em UTF-8). Outra forma é usar referência numérica hexadecimal no formato: &#xCODE; :contentReference[oaicite:15]{index=15}

Básico

Emoji não é imagem. É caractere. Se o navegador e a fonte suportarem, ele aparece. :contentReference[oaicite:16]{index=16}

✅ Dica: Comece pelo mais simples: copie o emoji 😄 e cole dentro do seu <p>.

Intermediário

Quando você usa &#xCODE;, esse CODE é o código do Unicode em hexadecimal. Exemplo: &#x1F680; 🚀 :contentReference[oaicite:17]{index=17}

Avançado (boas práticas e pegadinhas)

  • Compatibilidade: alguns emojis são novos e podem aparecer diferentes (ou como “quadrado”) em sistemas antigos. :contentReference[oaicite:18]{index=18}
  • Consistência visual: emojis mudam de estilo entre Android/iOS/Windows. Use com intenção.
  • Fallback: se o emoji for “decorativo”, ok. Se ele carrega significado importante, inclua texto junto.
🧠 Por que isso importa? Você ganha velocidade e leveza: usar Unicode evita carregar imagens extras só para “decorar” a interface. :contentReference[oaicite:19]{index=19}

🔎 Exemplo (emoji + texto, mais acessível):

<p>✅ Cadastro realizado com sucesso</p>
<p>⚠️ Verifique seu e-mail para confirmar</p>

Resumo final

  • Emoji é Unicode (caractere), não imagem :contentReference[oaicite:20]{index=20}
  • Você pode colar direto (UTF-8) ou usar &#xCODE; :contentReference[oaicite:21]{index=21}
  • Use com consistência e cuide da compatibilidade

Mini-checklist

  • Minha página está em UTF-8 (meta charset)?
  • O emoji é decorativo ou carrega informação? (Se carrega, inclua texto junto.)

Perguntas rápidas

  2. O que significa o x em &#xCODE;?
✅ Dica: quando usar muitos emojis, mantenha consistência (mesmo estilo/tema), senão o layout vira carnaval fora de época 😄
